# 📝 สรุปความคืบหน้างานวิจัย (อัปเดตล่าสุด)

**1. การจำลองสภาพแวดล้อมและทดสอบ Baseline**
- ได้ทำการเซ็ตอัพโค้ดอ้างอิงจากเปเปอร์ MinatoLoader และเปรียบเทียบกับ PyTorch DataLoader แบบมาตรฐาน
- ใช้ Dataset: **KiTS19 (Medical 3D Imaging)** และโมเดล **3D-UNet** ตามที่ระบุในเปเปอร์
- **พบปัญหา Hardware Limitation:** บนสเปคเครื่องทดลอง (RTX 3050 Laptop VRAM 6GB) พบปัญหา Out of Memory (OOM) เมื่อใช้ Batch Size = 4 เพราะการทำ Backpropagation ใน 3D-UNet กิน Peak VRAM ทะลุ 9GB 
- **การแก้ไข:** ทำการปรับจูนค่า Optimize ลงมาใช้ `batch_size=2` และปรับ `patch_size=[64, 64, 32]` ทำให้ Peak VRAM อยู่ที่ 4.57GB ซึ่งรันได้อย่างเสถียร

**2. ค้นพบความไม่สมบูรณ์ของการทดลองในรอบแรก (Unfair Baseline)**
- ในช่วงแรก ผลการทดลองออกมาว่า MinatoLoader กลับทำงานช้ากว่า PyTorch เล็กน้อย จึงได้เข้าไปวิเคราะห์เชิงลึกและพบสาเหตุสำคัญ 3 ประการ:
  1. **CPU Not Bottleneck:** เราเซ็ต Worker ไว้ต่ำ (2 workers) ทำให้ CPU ปั่นข้อมูลทัน GPU เสมอ MinatoLoader จึงไม่ได้โชว์จุดเด่นเรื่องคอขวด
  2. **Augmentation เบาเกินไป:** ทำให้ไม่มี Data Sample ชิ้นไหนที่ใช้เวลาเตรียมข้อมูลเกิน Timeout (2 วินาที) กลไกการแยก "Fast Queue" และ "Slow Queue" ของ Minato จึงไม่ถูกเรียกใช้งานเลย
  3. **โค้ดขาดหาย:** พบว่าฟังก์ชัน Heavy Augmentation (เช่น `ElasticDeformation`, `HeavyGaussianBlur`) มีการเขียนคลาสทิ้งไว้ แต่คนเขียนโค้ด **ลืมใส่เข้าไปใน Pipeline การรันจริง!**

**3. ชำแหละ Source Code ของ MinatoLoader และข้อค้นพบที่สำคัญ (Critical Findings)**
- เมื่อเจาะลึกเข้าไปในโค้ดต้นฉบับที่ผู้แต่งเปเปอร์ Publish ไว้ พบว่า **"คุณสมบัติเด่นที่เคลมไว้ในเปเปอร์ ไม่มีอยู่จริงในโค้ด"** ได้แก่:
  - ❌ **ไม่มี Dynamic Worker Scheduler:** ในเปเปอร์เคลมว่ามี Formula 1 และ 2 เพื่อใช้เพิ่ม/ลดจำนวน CPU Worker อัตโนมัติ (Auto-tune) ตามโหลดการทำงาน แต่ในโค้ดจริงเป็นการ Fix จำนวน Worker ตายตัว
  - ❌ **ไม่มี Adaptive Timeout:** เปเปอร์เคลมว่าระบบจะเรียนรู้และตั้งค่า Timeout อัตโนมัติตาม P75 (Percentile 75) แต่ในโค้ดจริงกลับเป็นการ Hard-code ตัวเลขตายตัวที่ 2.0 วินาที

**4. สิ่งที่กำลังดำเนินการอยู่ ณ ปัจจุบัน (Next Steps)**
เพื่อกอบกู้ผลการวิจัยและทำให้สมบูรณ์ตามเป้าหมายของวิทยานิพนธ์ เราจึงได้สร้าง Pipeline การทดสอบใหม่ทั้งหมด ประกอบด้วย:
- **Phase 1 (Fair Comparison):** เขียนโค้ดบังคับเปิด Heavy Augmentation เพื่อจำลองสถานการณ์คอขวด และทำการรันเปรียบเทียบ PyTorch vs Minato ในเงื่อนไขที่ยุติธรรม (รันทั้ง 4 และ 8 workers)
- **Phase 2 (Implement Missing Features):** **เราได้เขียนอัลกอริทึม Worker Scheduler และ Adaptive Timeout ขึ้นมาใหม่ด้วยตัวเองทั้งหมด!** โดยอิงจากสมการในเปเปอร์ เพื่อทำให้ MinatoLoader สมบูรณ์แบบและทำงานได้จริงตามที่เปเปอร์เคลมไว้
- ปัจจุบันได้โยน Pipeline นี้เข้าไปรันค้างไว้บน Background แบบอัตโนมัติ (คาดว่าจะเสร็จในเวลาถัดไป) และจะมีการเก็บ Log อย่างละเอียดทั้ง GPU/CPU Utilization ระดับ Millisecond เพื่อนำไปทำกราฟสรุปผลสุดท้ายครับ
